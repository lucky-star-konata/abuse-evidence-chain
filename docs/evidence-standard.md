# 证据规范

## 1. 采集前提

- 只访问公开页面，不做登录、爆破、漏洞验证、批量爬取
- 采集前确认当地法律与平台规则允许
- 同一目标只做一次最小化请求，避免对目标造成压力

## 2. 必采字段

| 字段 | 为什么需要 |
| --- | --- |
| 完整 URL 与最终 URL | 证明证据来自哪里，跳转链是否一致 |
| 采集时间（带时区） | 页面会换壳，时间是关联关键 |
| HTTP 状态与响应头 | 证明页面当时真实存在 |
| 页面原始字节 | 截图可被质疑，原始文件可重算哈希 |
| 文件 SHA-256 | 完整性校验的唯一依据 |
| TLS 证书信息 | 关联同一团伙的其他域名 |
| DNS 解析结果 | 关联托管与基础设施 |
| WHOIS / RDAP | 注册商与注册时间 |

## 3. 完整性

- 采集完成后立即生成 `manifest.json`，写入每个文件的大小与 SHA-256
- 任何转交、归档、提交前都跑一次 `verify_chain.py`
- 不要手工编辑证据文件；需要标注时新建说明文件
- 原始目录只读保存，分析副本另存

## 4. 时间与来源

- 时间统一带时区（如 `+08:00`）
- 记录采集者、工具版本、网络出口国家/地区（如适用）
- 截图与文件对应关系写进报告，避免"图不对文"

## 5. 脱敏

- 受害人姓名、手机号、身份证号、银行卡号默认打码
- 聊天记录只保留与案件相关片段，隐去无关人员
- 公开举报材料不放原始个人信息，原始件单独受限分发

## 6. 保存与销毁

- 证据目录不进公开仓库（`.gitignore` 已排除 `cases/`）
- 设定保存期限，到期销毁并留销毁记录
- 跨方共享时记录接收方、用途、时间

## 7. 常见错误

- 只存截图，没有原始页面和哈希
- 用浏览器插件改过页面后再保存
- 时间只写"今天下午"
- 把多个站点的证据混在一个目录，无法定位来源
- 举报材料里写推测性结论，削弱可信度
